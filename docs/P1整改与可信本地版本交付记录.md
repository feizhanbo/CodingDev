## 2. 配置及兼容变化

| 配置 | 默认值 | 含义 |
|---|---|---|
| DEVPILOT_MAX_LLM_REQUESTS | 90 | 每次运行所有模型尝试累计上限 |
| DEVPILOT_LLM_TIMEOUT_SECONDS | 120 | 单次模型请求等待上限，受剩余执行时间进一步约束 |
| DEVPILOT_MAX_RUN_SECONDS | 1800 | 工作区准备完成后的自动执行阶段截止时间 |
| DEVPILOT_WORKSPACE_MAX_BYTES | 268435456 | 单工作区允许文件的逻辑容量，256 MiB |
| DEVPILOT_WORKSPACE_TOTAL_MAX_BYTES | 2147483648 | 所有工作区允许文件的逻辑容量，2 GiB |

`max_steps=30` 及已有重试、修改范围限制保留，工具步数不改成模型请求数。模型每轮最多三次异常重试，同时受总请求数约束。已有 `network_access` 值不构成防火墙策略；提示与结果改为明确 `trusted_local`。

结果新增可选 termination_reason、budget、artifact_errors、recovery_file，旧运行结果仍能 inspect。Token 统计保留 unknown/null 和 known_tokens 两种口径，不生成未经证实的金额。

API 正常响应结构保持不变。数量必须为严格正整数（拒绝 bool、小数），空单拒绝；重复商品合并为一行。库存不足、不存在客户/商品保持 400；重复支付 409；数据库锁忙碌 503；分页不合法 422。支付和取消仍是本地状态模拟。

Repository 写方法现在不自行 commit；直接使用 Repository 的调用者必须显式提交。Service 负责其业务事务，原测试中的 Repository 调用与状态准备代码已适配。未迁移数据库，未更换 Float 金额模型。

内置 eval/benchmark-check 不再默认读取当前 ShopFlow 目录。显式 `--base-repo` 遇到哈希差异应失败；这是防漂移约束，不能通过自动更新 manifest 绕过。普通 run 与自定义任务仍操作目标项目副本。

## 4. 操作说明与保留策略

```powershell
# 从 devpilot 目录使用已有解释器，不调用模型。
.venv/Scripts/python.exe -m devpilot.cli workspace-report --retention-days 7
.venv/Scripts/python.exe -m devpilot.cli benchmark-check `
  --test-python G:/program/CodingDev/shopflow-order-service/.venv/Scripts/python.exe `
  --output G:/program/CodingDev/runs/new-benchmark-evidence
```

benchmark 输出目录应是全新目录。workspace-report 只列容量及已结束旧任务的人工归档候选，不删除任何文件。逻辑容量不包含 Git 对象、trusted 快照、日志和独立验收副本；本轮不声称已完全解决长期磁盘增长。

state.json 在决策之间保存，用于定位最后观察到的状态；不能把它解释为已支持断点继续。若常规写盘失败，结果中给出 artifact_errors 和可能的 recovery_file；系统临时目录也不可写时会明确报告无法恢复，不虚构已保存证据。

## 5. 保留的风险和后续边界

- **R-01/P1 保留：** Python 与宿主同权限执行，环境白名单不阻止代码主动访问宿主文件、网络或创建进程。本轮只允许可信本地场景；容器或低权限执行环境另立开发任务。
- **R-02 剩余风险：** 禁止文件规则和已知密钥脱敏无法证明仓库不存在未知秘密，也无法防御任意恶意候选代码；最终差异与冻结代码不是伪造的脱敏版本。
- **S-05/P1（对外前）与 R-09 交易部分保留：** 无公网认证/对象权限、真实支付退款和定点金额迁移；不得把样例当生产电商服务。
- 模型真实能力未评测。固定决策冒烟验证执行链，参考补丁自检验证数据集，均不计算真实 AI 成功率。
- 仍没有自动 resume、强制进程树隔离、runs 全局配额或自动清理；不因本轮接线和诊断完善就宣称这些能力已实现。
