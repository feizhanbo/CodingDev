## 2. 恢复协议与执行行为

### 2.1 检查点内容

`devpilot/devpilot/runtime/custom/recovery.py::Checkpoint` 定义版本 1 协议。`CustomAgentRunner._checkpoint` 原子写入 `runs/<run_id>/checkpoint.json`，同时保留可供旧 inspect 使用的 `state.json`。检查点包含：

- 原 run_id（新任务分配发生冲突时不会复用旧目录）、任务、阶段、观察、工具步数、测试重试次数和修复标志。
- 累计模型请求数、本轮已尝试次数、原执行截止时刻及保存时剩余时间。
- LoopGuard 的重复动作、计划循环、补丁失败计数，以及 MetricsCollector 的已知请求/Token/工具统计。
- 工作区和 trusted 目录的文件 SHA-256；恢复校验包括 Git、数据库及生成文件，拒绝链接和禁止凭据路径。
- RuntimeConfig，以及源码、Python/平台、目标测试解释器和模型配置的摘要指纹。模型密钥、完整环境和原始服务地址不写入协议。

冻结证据及最终 diff 保留实际代码内容，不通过脱敏篡改哈希。检查点中的已知配置密钥仍按现有日志策略脱敏；未知秘密和恶意宿主代码不属于该协议能够防御的威胁。

### 2.2 可恢复与拒绝条件

| 持久阶段 | 行为 |
|---|---|
| ready | 恢复已记录的状态，再申请下一次模型请求 |
| llm_inflight | 认为前一次请求已消耗预算；账单 Token 不明时记 unknown；只使用本轮剩余尝试次数 |
| tool_inflight | 拒绝。无法判断工具副作用完成到哪一步，不重放 |
| verifier_inflight | 拒绝。保留独立验收证据供检查，不擅自重新验收 |
| terminal 或已有 result.json | 拒绝。终态任务应 inspect 或另建任务 |
| eval 任务、旧版无 checkpoint、代码/配置/文件不兼容 | 拒绝。能力评估需重新完整运行 |

恢复采用原截止时间与保存的剩余预算中更小者，停机耗时计入预算，且不允许通过重启将单轮三次重试归零。进程被操作系统结束后，内核文件锁自动释放；另一个实例仍持锁时立即拒绝恢复。普通客户端连接配置可轮换密钥，但模型、地址、参数、解释器或源码改变会拒绝恢复。

检查点是可信宿主的运行账本，不是防篡改签名文件；它不能抵抗同权限恶意代码主动修改账本或宿主时钟。不宣称任意副作用的 exactly-once、热迁移或旧版本检查点升级。每个调度边界的全量哈希会增加磁盘 I/O，大仓库的恢复成本仍需单独测量。

### 2.3 使用方式

从原配置的同一工作目录执行：

```powershell
.venv/Scripts/python.exe -m devpilot.cli inspect run_1234abcd
.venv/Scripts/python.exe -m devpilot.cli resume run_1234abcd --env-file .env
```

如原任务显式指定目标解释器，恢复时也提供相同的 `--test-python`。先人工确认任务为何中断；不可恢复时根据已有 diff、state、测试日志和 trusted 证据另建任务。临时目录 `recovery_file` 是诊断兜底，不能当可恢复检查点传给 resume。`--fake` 不提供断点续跑 CLI；回归测试直接注入确定性 FakeLLM 响应验证恢复。

## 3. 进程生命周期、输出与截止时间

`devpilot/devpilot/processes.py::run_process` 统一供 `test.run` 和可见/新增/隐藏独立测试使用：

1. 子进程继承现有环境白名单。stdout/stderr 合并流式读取，不再先将全部输出缓存在宿主内存中。
2. 输入字节和写入日志字节均有限额；非法 UTF-8 替换或已知密钥脱敏膨胀也不能绕过日志限制。跨读取块的完整已知密钥可脱敏。
3. 输出超限、超时和取消会终止本次拥有的进程树，保留有限部分日志；测试结果为 ERROR，不根据可能残留的 XML 宣称通过。
4. POSIX 使用新进程会话/进程组；Windows 使用私有 Job Object 的 KILL_ON_JOB_CLOSE，可信启动器先等待，再在加入 Job 后启动候选测试，Job 绑定失败时不启动候选代码。
5. 父测试进程正常结束时也清理其残留子进程，避免后代仍持有输出管道。异步取消设置工作线程的取消事件并等待清理，避免放弃线程后继续跑测试。

运行时在工具和验收的 await 前设置剩余时间上限，并在返回后复查截止时间。进程退出/线程收尾有额外的有限等待；同步 Git、目录扫描、快照复制及磁盘系统调用不能被 Python 的异步取消强行抢占，因此不承诺宿主所有代码严格在截止时刻终止。候选代码主动脱离进程组、操作宿主或访问网络的恶意行为仍由 R-01 追踪。

Windows 结构及生命周期实现参考 Microsoft 的 [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[扩展限制结构](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information) 和 [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject)。本地实际执行了 Windows 子进程心跳/取消/绑定失败回归，以及禁用 UTF-8 默认模式时的中文检查点恢复；Linux 用相同回归中的进程组分支，由现有 CI 矩阵执行，本地未伪称已跑远端 CI。

## 4. 容量与保留

| 新配置（DEVPILOT_ 前缀） | 默认 | 实际含义 |
|---|---|---|
| MAX_TEST_OUTPUT_BYTES | 2097152 | 每次测试最多 2 MiB 输出内容，另有固定截断标记 |
| RUN_ARTIFACTS_MAX_BYTES | 536870912 | 单 agent run 的产物容量准入，512 MiB |
| RUNS_TOTAL_MAX_BYTES | 4294967296 | 所配置 runs 根目录总容量准入，4 GiB |

`storage.tree_bytes` 对目录内全部常规文件计数，不跳过 Git/日志/数据库，不解引用链接。`SandboxWorkspace.check_artifacts` 在准备、循环、测试和最终验收前检查容量，并为输出和副本估算预留；隐藏验收也检查。超过门槛停止调度，结果为 `artifact_quota`。用于解释失败的 state/checkpoint/result/llm-requests/eval_result JSON 豁免拒写，不删除任何既有文件。

`workspace-report --retention-days 7` 仍为只读；列出工作区及产物容量、工作区逻辑/物理字节、配置门槛与已结束旧任务的人工归档候选。默认保留全部证据。

这些门槛不是原子磁盘预留：两个不同 run 可在检查后并发增长，候选 Python 可自行写任意文件，JUnit XML/临时文件可能超过估算。诊断 JSON 和直接追加的 trace 也可使总量略超限。独立 benchmark-check 的输出目录不冒充 agent run 配额。磁盘监控、人工归档、操作系统硬配额及低权限执行环境仍需后续设计。
