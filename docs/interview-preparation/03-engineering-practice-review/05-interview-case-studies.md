# 六个重点案例素材

以下均以“项目实现”叙述，不预设本人独立完成。每例的历史/代码证据对应[问题复盘](02-engineering-problem-retrospective.md) P 编号；确定贡献后再调整主语。不是固定背诵答案。

## 案例一：迁移编排引擎而保留业务契约（P08）

- **背景**：本地 Agent 已有工具、状态与验收，需要显式图编排和持久恢复。
- **挑战**：迁移后不能绕过旧预算、修复和验证规则，也不能误用新默认值恢复旧任务。
- **思路/实现**：ApplicationRuntime 稳定入口，shared steps/lifecycle 承担业务，Graph 负责节点路由；manifest 选择历史引擎。
- **原理**：依赖抽象、运行期对象隔离、调度状态与领域状态分离。
- **取舍**：保留 Custom 回退和契约对照，增加双引擎维护及序列化成本。
- **效果证据**：test_graph_business_contracts 复用旧业务断言；历史性能记录明确成本增加，不宣称提速。
- **价值/反思**：体现渐进迁移和验收意识；框架没有接管工具权限与全部恢复语义。
- **切入点**：为什么“换框架”不能只替换入口调用。

**简述素材**：项目把编排和业务规则拆开，在引入图运行时的同时保留原有验证、预算及回退路径。

**技术展开**：CLI/Eval 只依赖 RunRequest/RunOutcome；两个 runner 共用步骤但有不同恢复机制。测试在构建边界替换引擎并保留业务断言，恢复按 manifest 而非当前默认值路由。

**深入话题**：协议边界、可变状态隔离、旧 checkpoint 兼容、存储成本、如何退出兼容期。

## 案例二：让任务完成建立在独立证据上（P01）

- **背景**：模型会声明完成，也能修改目标文件。
- **挑战**：修改测试和漏记文件可能导致虚假成功。
- **思路/实现**：trusted snapshot、文件清单、candidate、独立 visible/added/hidden 测试，smoke 不计能力率。
- **原理**：信任边界、内容摘要、独立验收与指标定义。
- **取舍**：额外复制/测试开销换取可审查证据，不能证明未覆盖需求。
- **效果**：删除冻结测试、未跟踪新增文件和新增简单测试的相关回归断言支持行为变化。
- **价值/反思**：体现 AI 可靠性判断；同机测试非安全隔离，coverage 仍有限。
- **切入点**：为什么不能相信 test.run 或模型 summary。

**简述素材**：项目将模型的完成请求与系统确认完成分离，通过冻结基线和独立测试产生验收证据。

**技术展开**：verify 不只读 Agent state，而是重新计算文件差异并物化候选；新增测试不能覆盖原测试失败。评测报告明确区分未测、错误、失败和通过。

**深入话题**：测试污染、未跟踪文件、验收覆盖、基准数据泄漏、指标分母。

## 案例三：处理 checkpoint 与工具副作用的崩溃窗口（P03）

- **背景**：工具已改文件但图状态未保存时，节点可能重新执行。
- **挑战**：无法用一个 SQLite 事务同时提交普通文件和远端调用。
- **思路/实现**：OperationJournal prepared/completed，校验参数、工作区和结果摘要；确定完成才复用。
- **原理**：失败窗口、幂等与结果复用、恢复准入。
- **取舍**：不确定工具操作停机待检查，降低自动恢复率以避免盲目重复。
- **效果**：回执写失败、参数漂移、completed 前后中断都有对应测试。
- **价值/反思**：体现系统一致性思考，不是 exactly-once；模型请求有单独记账策略。
- **切入点**：有 checkpoint 为什么还要写回执。

**简述素材**：项目没有把图恢复等同于工具可安全重试，而是通过持久化回执区分已完成和不确定操作。

**技术展开**：begin 保存意图，工具返回后 complete 保存结果；恢复只有参数及 after 摘要匹配才返回旧结果。prepared 即使工作区看似没变也不能证明无副作用。

**深入话题**：2PC 区别、远端幂等键、未知模型费用、终态发布、文件锁范围。

## 案例四：从超时参数走向任务资源所有权（P04）

- **背景**：Agent 循环会重复模型和测试调用。
- **挑战**：超时后线程/子进程可能继续工作，恢复可能重复获得预算。
- **思路/实现**：RunBudget 贯穿任务，模型次数持久化，Event 协作取消，进程树停止并等待 I/O 清理。
- **原理**：Task 取消、线程协作、进程所有权、累计计账。
- **取舍**：等待清理可能超出设定秒数；平台专用实现复杂。
- **效果**：test_processes 验证输出上限、子进程终止和取消等待；恢复测试约束预算不重置。
- **价值/反思**：体现异步后端基本功深入应用，不是硬资源沙箱。
- **切入点**：await 超时后谁负责停止实际工作。

**简述素材**：项目把超时从单个调用参数提升为全任务预算，并为测试/Git 子进程定义明确的清理责任。

**技术展开**：上层 timeout 请求取消，worker 收到 Event 后清理进程树；调用方继续等待清理才传播取消。恢复沿用原 deadline 和次数，未知用量不记作零。

**深入话题**：shield、wait_for、Windows Job、日志字节限额、多 worker 准入。

## 案例五：限制模型驱动的文件副作用（P07，结合当前 E5）

- **背景**：模型可提供任意路径和 patch，清理逻辑也可能接收异常 run_id。
- **挑战**：检查必须针对最终操作路径；失败修改需要恢复，恢复材料本身也有容量。
- **思路/实现**：resolve 后验证、链接拒绝、冻结测试写保护、Git numstat/check、保存原文件并限制大小；删除校验修正最终目标。
- **原理**：路径规范化、检查与使用边界、可逆操作与崩溃恢复差别。
- **取舍**：更严格限制拒绝部分大补丁；强杀与外部并发改动仍有风险。
- **效果**：dccd2ba 的危险路径测试断言 rmtree 未调用；patch 原子性测试验证混合无效补丁不改变文件。
- **价值/反思**：体现防御性边界设计，不能称为完整安全沙箱。
- **切入点**：为什么校验父路径和校验目标规范化后的父路径不同。

**简述素材**：项目不仅校验模型声明的路径，也用 Git 解析实际修改目标，并对清理与失败回滚建立边界。

**技术展开**：路径防护和受保护文件策略分别解决“在哪里写”和“哪些证据不能改”；apply 前 check，异常时恢复原 bytes，但进程强杀必须交给恢复机制处理。

**深入话题**：符号链接、TOCTOU、磁盘满、check/apply 非事务、未跟踪文件。

## 案例六：把订单与库存放回同一业务事务（P02）

- **背景**：ShopFlow 创建/取消跨订单、明细和库存。
- **挑战**：多个 Repository 独立提交会留下部分成功；重复取消不能重复加库存。
- **思路/实现**：Service 统一提交，Repository flush，库存条件 UPDATE，状态 CAS 争取一次回补资格。
- **原理**：事务原子性、条件更新、状态幂等。
- **取舍**：单库方案直接；SQLite 写竞争与请求级幂等仍需另行治理。
- **效果**：故障注入验证库存/订单整体回滚，重复取消和并发同类请求有回归断言。
- **价值/反思**：体现业务不变量与提交边界；不是支付系统或分布式事务成果。
- **切入点**：为什么不能让每个 Repository 自己 commit。

**简述素材**：项目将库存扣减、订单和明细写入统一到一个事务，并用条件状态迁移控制取消回补只发生一次。

**技术展开**：先合并商品数量，再数据库内检查 stock+delta≥0；订单创建只 flush，最后 Service commit。取消只有状态更新成功才还库存，重复取消返回现有状态。

**深入话题**：flush/commit、rowcount、锁失败、下单幂等键、commit 成功但响应丢失。
