## 保留、替换与新增复杂度

- 保留：DeveloperAgent 的决策边界、工具 Registry、领域模型、独立 Verifier、确定性 Fake 和旧 Custom 兼容路径。
- 替换/重组：默认编排改 Graph，默认模型适配改 LangChain；业务步骤从旧大循环抽到 shared，CLI/Eval 走应用契约。
- 新增：GraphState 投影、SQLite 产物容量、回执对账、manifest 身份、终态发布时机、框架依赖兼容校验。
- 重要判断：框架减少手写调度负担，不会消除外部副作用和证据一致性的应用责任；工具和验证越严格，迁移越需要契约测试。

## 技术债务与改进优先级（均为 P）

| 优先级 | 当前不足 | 建议与触发条件 | 如何证明改进 |
| --- | --- | --- | --- |
| 高 | 自然语言验收多数未绑定检查 | 为重要条件显式配置 check，并保留 uncovered | 对有/无检查条件分别断言报告；不能只统计总通过数 |
| 高 | ShopFlow 下单无请求级幂等 | 若面对网络重试，增加幂等键、唯一约束和响应复用规则 | 提交后响应丢失、相同键不同参数、多并发重复请求 |
| 高 | 工具不确定副作用需人工处理 | 为可安全幂等工具定义对账规则；远端集成要求服务端幂等 | 各崩溃窗口恢复不重复副作用且能解释未知状态 |
| 中 | 双运行时兼容维护成本 | 定义保留期限与历史 run 处理政策，先量化真实使用 | 旧任务读取/拒绝/迁移契约不被静默改变 |
| 中 | context 字符预算与有损摘要 | 必要时引入精确 tokenizer 和证据引用，不直接上向量库 | 预算及关键失败保留测试，真实任务样本对比 |
| 中 | JSON 兜底扫描不识别字符串括号 | 使用正式解析位置机制并完善边界用例 | 杂文、转义、花括号字符串、多对象输入 |
| 中 | 全量清单/复制/SQLite 写入成本 | 在大仓库或多任务需求出现后 profile，再优化增量策略 | 保持证据一致性与恢复契约的配对测量 |
| 中 | 订单金额 float、错误文本分类 | 金额精度要求出现时改 Decimal/最小单位，定义领域异常 | 边界金额和 HTTP 映射回归 |
| 条件触发 | 可信本地执行限制 | 接收不可信仓库或多租户前引入 OS 隔离与权限治理 | 独立隔离验收；当前路径测试不够 |

不能为了减少延迟去关闭同步 checkpoint、跳过验收或清空累计预算；这会改变系统承诺，而非等价优化。

## 如果重新设计

值得保留：先定义成功证据，再构造 Agent 循环；把事务边界放在业务不变量处；让重试/预算有明确所有者；尽早写失败注入测试。

值得调整：更早形成 RuntimePort 和不可混淆的结果类型；把恢复窗口和未知状态写入契约；建立验收条件映射；从第一版就统一编码、路径规范化和子进程所有权。以上是事后反思，不能写成作者当时已完整规划。

## 证据表述修正

前两阶段“并发支付/取消”应收紧为“并发支付及并发取消两个阶段”，现有该测试不证明支付与取消混合竞争。其余应持续保留的边界：模型与工具恢复不同；rollback 不撤销成功提交；普通测试不等于全部需求；Fake 不等于真实模型能力；本地进程治理不等于恶意代码隔离。

## 第四阶段题库重点

围绕六个案例各建立“业务→实现→原理→权衡→故障场景”追问链。优先考察：验收证据是否可信、prepared 为何不能重放、未知模型请求怎样计账、取消后资源是否停止、flush/commit 区别、提交成功但响应丢失、双引擎契约与恢复兼容、路径检查与强杀窗口。

每题区分当前实现答案与扩展设计答案；将 mixed pay/cancel、请求幂等、多 worker 和恶意代码隔离作为尚未完成能力的场景分析，不暗示已落地。正式参考回答留在第四阶段，不在此扩充通用八股。
