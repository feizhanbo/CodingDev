# 后续阶段具体梳理重点

本轮不提前生成完整问答和话术。以下为基于当前代码的分阶段工作安排。

## 第二阶段：核心技术深度解析

建议按以下独立文档逐篇完成，每篇遵循“业务需求→技术方案→核心实现→原理→权衡→异常处理→优化空间”，附调用链、关键代码和失败时间线。

1. **可信验证与评测**：从 finish 追踪到 verify、candidate、独立 suite、hidden acceptance；核对测试污染防护、零测试/跳过/超时语义、uncovered 条件，比较 smoke 与 capability。
2. **恢复与一致性**：逐层追踪 graph checkpoint、manifest、OperationJournal、模型账本、终态发布；覆盖副作用前/后、回执前/后、checkpoint 前/后的崩溃窗口。解释何时复用、何时拒绝、何时需要人工处理。
3. **全任务资源预算**：从入口到模型、工具、测试、隐藏评测逐层追踪 deadline；解释单调时钟与跨重启时间、请求未知用量、取消线程/进程树、磁盘准入及诊断保留。
4. **订单事务和并发**：绘制创建/支付/取消 SQL 时间线，复盘 flush/commit、条件 UPDATE、rowcount、SQLite 锁竞争。区分状态 CAS、库存原子扣减、重复取消和请求幂等。
5. **框架迁移与上下文**：对照 Custom 与 Graph 共享步骤，解释为什么适配器不直接承担全部业务；追踪计划、失败反馈和上下文裁剪。补充 JSON 模型协议与原生 tool calling 的区别。
6. **受控工具与文件副作用**：逐层核验 PathGuard、可信文件保护、补丁目标枚举、异常回滚与强杀限制；明确宿主执行与容器隔离的差距。

完成标准：能按代码解释一条成功路径和至少两条失败路径，能给出替代方案并说明它尚未落地。

## 第四阶段：五层题库与连续追问

围绕实际模块组织，而不是按框架名堆题。每题补齐考察能力、实际回答、原理、后续追问、回答方向、源码位置。

| 主问题 | 连续追问方向 |
| --- | --- |
| 为什么模型说完成不能直接返回成功？ | 修改测试怎么办→隐藏测试如何隔离→测试通过但条件 uncovered 怎么表达 |
| 有 checkpoint 为什么还要回执？ | 写文件后崩溃→prepared 能否重试→远程支付副作用如何设计幂等 |
| 超时后任务真的停止了吗？ | await 取消与线程继续执行→子进程树→重启能否重置预算 |
| 为什么库存不用先读再减？ | 条件更新与事务→两个请求竞争→取消回补→下单幂等键 |
| 为什么引入 LangGraph？ | 自研循环代价→共享服务契约→持久化成本→十倍任务规模 |
| 上下文超长如何处理？ | 必须保留哪些证据→字符与 token→失败反馈被裁剪→何时才需要 RAG |

假设性回答需标为“若扩展系统”，包括消息队列、分布式锁、PostgreSQL、容器、向量检索等；不混入当前项目介绍。
