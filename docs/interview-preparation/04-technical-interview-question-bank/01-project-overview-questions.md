# 项目整体理解

题号用于跨文档关联。代码缩写与精确源码链接见 README 证据索引；“扩展”不是已实现功能。评价分为合格、深入和警惕三档。

## O01｜P0·初级｜DevPilot 和 ShopFlow 分别解决什么问题？

**考察**：业务定位与事实边界。

**简答**：DevPilot 是把研发 Issue 转成代码修改、测试、修复和可审查交付的本地单 Agent 平台；ShopFlow 是被它操作和评测的订单后端，也提供事务实践案例。

**展开**：DevPilot 的价值在约束不确定决策并产生可信证据，不只是生成代码。ShopFlow 的客户、商品、订单、优惠券是受控业务载体，不是已验证商业规模的电商平台；它的业务 SQLite 与 Agent checkpoint 各自负责不同数据。

**原理/追问**：执行系统与被执行系统为何要分开？分别维护工具/验收规则与订单业务，避免把测试目标和裁判混为一体。继续 O02。

**证据**：R、V、D。**评价**：合格能分清两个项目；深入能说出信任边界；把单 Agent 讲成多 Agent 或生产平台需纠正。

## O02｜P0·中级｜从命令入口讲完一次任务，在哪一步才算成功？

**考察**：端到端调用链。

**简答**：CLI/Eval 经 ApplicationRuntime 装配本次依赖，建立工作区和冻结基线，进入决策—工具—观察循环；finish 必须经过 Verifier，成功证据和终态落盘也要完成。

**展开**：图按 prepare/guard/context/decide 推进，决策分 action、plan_update、finish。工具结果经 StateManager 成为 Observation，再构造下一轮上下文。verify 拒绝会回修复，不直接结束；图持久化失败也不能仅凭内存 completed 宣告交付。

**原理/追问**：业务状态、调度状态、持久化状态不同。追问“测试绿了为何还会失败？”看 S04；“图节点与 phase 相同吗？”看 A01。

**证据**：R、V、J。**评价**：合格说全闭环；深入指出两个完成边界；只列框架名称不合格。

## O03｜P0·中级｜项目目前有哪些能力，哪些还没有？

**考察**：交付边界。

**简答**：当前有本地单 Agent、双运行时、受控工具、可信测试、预算、回执恢复和本地 Trace；没有证据支持分布式 Worker、恶意代码安全隔离、真实支付、RAG 或生产 SLO。

**展开**：默认 LangGraph/LangChain，Custom/OpenAI 是兼容路径。Fake 回归与确定性 benchmark 验证基础设施，不代表模型解题成功率；Langfuse 延期，不能把文档目录名当作接入事实。

**原理/追问**：功能存在、经过何种验证、在哪个环境有效是三个问题。追问“最先补哪项？”依据使用场景回答 D03，而非随意堆中间件。

**证据**：R、M、E；第三阶段演进记录。**评价**：主动说明限制可加分；编造用户量、吞吐或上线经历是严重扣分。

## O04｜P0·中级｜选一个真实改造，怎样证明它改进了系统？

**考察**：证据驱动复盘。

**简答**：订单事务改造最直接。34e6e7e 把 Repository 独立 commit 改为 flush，由 Service 统一提交；故障注入测试检查失败后库存、订单和明细整体回滚。

**展开**：旧流程先创建订单再逐项库存提交，会存在部分成功风险。新流程合并商品、条件扣减、创建明细后提交。测试覆盖第二商品失败、明细 flush 后失败和提交前失败，但不覆盖已成功提交后响应丢失；后者需要请求幂等。

**原理/追问**：提交边界与业务不变量。继续 B04/B05、追问链 T6。

**证据**：D；`tests/services/test_order_integrity.py:test_failure_rolls_back_everything`。**评价**：深入回答说明测试的断言及未覆盖范围，不能只说“测试都过了”。
