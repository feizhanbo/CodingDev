# 按岗位调整表达

## AI应用开发：先讲可信执行，再讲框架

**可口述开场**：

我想先介绍 DevPilot。它把研发 Issue 转成代码修改、测试和修复的闭环。我会重点讲模型决策进入后端之后，系统怎样限制工具、保存状态并独立判断任务有没有完成。LangGraph 负责流程推进，模型适配和 JSON 协议负责输入边界，而最终成功由验证器决定。

其中比较有代表性的是恢复设计：图 checkpoint 和文件修改不是同一个事务，所以项目增加操作回执，只复用有证据的已完成结果，不确定操作不盲目重放。另一个重点是评测口径，Fake smoke 只验证执行链路，不当作模型能力成功率。

ShopFlow 是这个 Agent 的目标业务仓库。我可以用它的库存和订单事务说明业务理解，但它没有真实支付或商业生产规模。我的实际参与是【待确认：具体模块与动作】。

**时间分配建议**：约六成讲 DevPilot 入口与验证，三成展开恢复或上下文，一个简短段落交代 ShopFlow 和边界。不要在开场一次讲完所有 E1–E8。

**自然转场**：“如果您更关注模型执行的可靠性，我可以接着说明它为什么不能只依赖 checkpoint。”接第四阶段 T3。若问提示词，转案例七；不要把规则压缩描述成 RAG。

## Python后端：先讲一致性，再讲异步执行

**可口述开场**：

这组项目有两个后端切入点。ShopFlow 是 FastAPI 和 SQLAlchemy 的订单服务，DevPilot 是执行研发任务的 Python Agent 平台。我会先用订单例子说明事务边界，再讲执行平台中的异步资源治理。

ShopFlow 创建订单时，把库存扣减、订单和明细放在同一事务里；库存通过条件 UPDATE 判断，而不是应用先查再写。取消只有状态迁移成功才回补库存，避免重复请求重复加库存。这些机制有失败注入和并发测试，但不能当作完整下单请求幂等或高并发生产证明。

DevPilot 则提供另一类可靠性问题：协程超时并不意味着线程或测试子进程停止。项目用全任务预算、取消通知和进程树所有权来管理生命周期，中断恢复也保留已消耗预算。我的实际工作范围是【待确认】，可以从【已确认案例】展开。

**时间分配建议**：偏业务后端岗位先讲 ShopFlow；偏平台、工具链或异步服务岗位先讲 DevPilot 的预算和恢复。两个项目始终分别命名，不把订单数据库和图 checkpoint 合成一个事务系统。

**自然转场**：“这个事务解决的是提交前的整体失败；如果提交成功后响应丢失，还需要另外的请求幂等设计。”接第四阶段 S06。

## 同一能力换一个强调点

| 内容 | AI应用表达 | Python后端表达 |
| --- | --- | --- |
| 独立验证 | 如何判断模型任务完成 | 执行者与验收证据的边界 |
| 回执恢复 | Agent中断后避免不安全重放 | 跨资源副作用与持久化窗口 |
| 预算 | 限制模型请求与修复循环 | deadline传播、取消和资源释放 |
| 上下文 | 保留最新失败和任务约束 | 状态投影、接口字段与数据一致性 |
| ShopFlow | 可验证的业务任务载体 | 原子SQL、事务和状态迁移 |

选择重点不是修改事实。个人不了解的模块不作为开场主亮点；能够讲清一个实现、一个失败路径和一个限制，比列出十项技术更有说服力。
